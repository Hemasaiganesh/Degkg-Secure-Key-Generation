DeGKG: Efficient Decentralized Inter-Group Key Generation

Satellite Signal-Based Cryptography • Chinese Remainder Theorem Aggregation • Blockchain Consensus • Post-Quantum Ready

1. Research Motivation IEEE TIFS 2026

Drone swarms are increasingly deployed in battlefield coordination, smart agriculture, disaster response, environmental monitoring, and urban air mobility. Secure communication between multiple geographically distributed swarms remains a critical challenge that traditional cryptographic solutions fail to address efficiently.

Limitations of existing approaches:

  • High computational overhead – Resource-constrained drones cannot perform heavy asymmetric cryptography
  • Poor scalability – Traditional group key agreement scales O(n²) with drone count
  • Single point of failure – Trusted third parties create security bottlenecks
  • Weak inter-swarm coordination – No efficient mechanism for cross-swarm secure channels

DeGKG addresses these limitations through a decentralized, hybrid physical-layer and cryptographic framework that leverages satellite entropy, CRT aggregation, and blockchain consensus.

2. System Architecture

The DeGKG architecture consists of four hierarchical layers:

  • Drone Swarms (Intra-Group Domain) – Each swarm contains 8-32 drones sharing satellite SNR correlation
  • Leading Drone (LD) – Performs key aggregation and represents the swarm in inter-group protocols
  • Ground Control Station (GCS) – Facilitates inter-swarm communication and blockchain interaction
  • Blockchain Consensus Network – Provides immutable key registry and Byzantine fault tolerance

Two-Layer Key Establishment Protocol:

Layer 1: Intra-Swarm Key Generation Satellite SNR → Quantization → Gray Coding → Fuzzy Extractor → Intra-Group Session Key (Kⱼ) Layer 2: Inter-Swarm Key Generation Kⱼ → Public Key (g^Kⱼ) → CRT Aggregation → Inter-Group Encryption Key (Kₑₙ) → Secure Distribution (K_cr)

3. Mathematical Foundations

3.1 Equal Probability SNR Quantization

F(bm) = m / M
Where M is number of quantization intervals, ensuring uniform entropy distribution across all intervals.

This preserves the maximum entropy from satellite signals while enabling error correction.

3.2 Fuzzy Extractor (Dodis et al.)

Gen(w) → (R, P) where R is extracted key, P is helper data
Rep(w', P) → R if dist(w, w') ≤ t (Hamming distance bound)

Guarantees consistent key extraction under bounded signal deviation (typical SNR variation ≤ 5dB).

3.3 Chinese Remainder Theorem Aggregation

M = ∏ mᵢ (pairwise co-prime moduli)
Mᵢ = M / mᵢ
Yᵢ ≡ Mᵢ⁻¹ (mod mᵢ) (modular inverse)
Kₑₙ = Σ (Mᵢ · Yᵢ · swᵢ) mod M

Efficiently integrates multiple swarm public keys with O(m) complexity instead of O(n).

3.4 Key Evolution with Forward Secrecy

Kᵢ = Rᵢ ⊕ SHA-256(Kᵢ₋₁)

Hash chain ensures forward secrecy (past keys protected) and backward secrecy (future keys unpredictable).

4. Security Model & Formal Proof Intuition

Security is formally analyzed under standard cryptographic assumptions:

  • Discrete Logarithm (DL) assumption – Hardness of computing discrete logs in prime-order groups
  • Computational Diffie-Hellman (CDH) – Hardness of computing g^{ab} from g^a and g^b
  • Decisional Diffie-Hellman (DDH) – Indistinguishability of (g^a, g^b, g^{ab}) from random triple

Security Properties Achieved:

  • Confidentiality – IND-CPA security under DDH assumption
  • Source Authentication – HMAC-SHA256 with session keys
  • Forward Secrecy – Compromise of current key does not reveal past keys
  • Backward Secrecy – Compromise does not reveal future keys
  • Byzantine Fault Tolerance – Consensus tolerates f ≤ ⌊(n-1)/3⌋ malicious nodes
Theorem 1 (Key Indistinguishability): If DDH assumption holds in group G, then any PPT adversary has negligible advantage in distinguishing DeGKG session keys from random.

Computational Complexity:

  • Independent of total drone count (n) – scales with number of swarms (m)
  • Drone-side: O(1) hashing and XOR operations
  • GCS-side: O(m) CRT aggregation and verification

Communication Complexity:

  • Short encryption key size proportional to m (typically < 1KB for 100 swarms)
  • Reduced ciphertext expansion compared to broadcast encryption schemes
  • Blockchain consensus amortizes inter-group coordination overhead

  • ⛓️ Blockchain-Based Decentralized Trust – Immutable key registry with Byzantine fault tolerance
  • 📈 Scalable Inter-Group Collaboration – Enables secure communication across 100+ swarms

7. Limitations & Future Research Directions

Current Limitations:

  • Physical Capture Attacks – Not resistant to drone compromise (mitigated by hardware security modules)
  • Classical Assumptions – Base protocol relies on ECDLP (addressed by post-quantum extension)
  • Blockchain Overhead – Consensus latency in ultra-constrained environments (optimized with light clients)

Future Research Directions:

  • Post-Quantum Inter-Swarm Key Establishment – Full migration to lattice-based cryptography (Kyber/Dilithium)
  • Physical-Layer Anti-Spoofing – AI-based GNSS spoofing detection using multi-constellation correlation
  • Lightweight Blockchain Consensus – Integration with IOTA or Nano for micro-transactions
  • Hardware Security Modules – PUF-based key storage and TEE for drone-side protection
  • Autonomous Key Rotation – ML-driven predictive key updates based on threat intelligence
