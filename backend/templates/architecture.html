Algorithm 1: Intra-Group Session Key Creation
Phase 1 • Key Establishment
INPUT: Satellite SNR signals from drones {s₁, s₂, ..., sₙ}
OUTPUT: Shared Intra-Group Session Key K

1. Collect SNR values from visible satellites for each drone
2. Quantize SNR values into M intervals → q₁, q₂, ..., qₖ
3. Convert quantized values to Gray code → g(q)
4. Apply Fuzzy Extractor:
      (R, P) = Gen(w) where w = g(q)
5. Broadcast helper data P to all swarm members
6. Each drone computes using its own w':
      R' = Rep(w', P)
7. Set Session Key:
      K = R'
8. Verify using hash: h(K) == stored_hash
Security Properties: Fuzzy extraction ensures key stability despite SNR variations. Gray coding minimizes bit errors during quantization. Achieves 256-bit entropy with satellite randomness.

📐 Mathematical Formulation:

K = Rep( FuzzyExtract( Gray( Quantize( SNRsat ) ) ), P )

Where: SNR ∈ [20, 60] dB, M = 28 quantization levels

Algorithm 2: Intra-Group Key Update
Phase 2 • Forward Secrecy
INPUT: Previous key Kᵢ₋₁, new satellite signals wᵢ
OUTPUT: Updated session key Kᵢ

1. Encode new SNR signals → wᵢ = Gray(Quantize(SNRᵢ))
2. Generate new fuzzy extractor output:
      (Rᵢ, Pᵢ) = Gen(wᵢ)
3. Compute updated key with forward secrecy:
      Kᵢ = Rᵢ ⊕ SHA-256(Kᵢ₋₁)
4. Broadcast helper data Pᵢ and hash for verification
5. All drones compute Kᵢ = Rep(wᵢ', Pᵢ) ⊕ h(Kᵢ₋₁)
6. Old key Kᵢ₋₁ is permanently discarded
Forward Secrecy Guarantee: Compromise of current key does not reveal previous keys. XOR with hash of previous key ensures one-way key evolution.

📐 Key Evolution Function: Kᵢ = Rᵢ ⊕ SHA-256(Kᵢ₋₁)

Property: Kᵢ₋₁ cannot be derived from Kᵢ (one-way function)

Algorithm 3: Swarm Public Key Generation
Phase 3 • Identity Management
INPUT: Intra-Group Key K (shared secret within swarm)
OUTPUT: Swarm Public Key sw (elliptic curve point)

1. Each Leading Drone selects elliptic curve parameters:
      secp256r1 (NIST P-256) or Curve25519
2. Compute swarm public key:
      sw = g^K mod p  (or scalar multiplication: sw = K · G)
3. Append timestamp and swarm_id to sw
4. Sign sw with leader's private key
5. Send signed sw to Ground Control Station (GCS)
6. GCS verifies signature and stores in blockchain registry
Blockchain Integration: Each swarm public key is anchored to the immutable ledger, enabling verifiable cross-swarm authentication.

📐 Elliptic Curve Construction: sw = K · G where G is base point, K ∈ [1, n-1]

Security: ECDLP hard with 256-bit keys → 128-bit quantum security

Algorithm 4: Inter-Group Encryption Key (CRT Aggregation)
Phase 4 • Swarm Federation
INPUT: Swarm public keys sw₁, sw₂, ..., swⱼ from J swarms
OUTPUT: Inter-Group Encryption Key Kₑₙ (CRT composite)

1. Choose pairwise co-prime moduli: m₁, m₂, ..., mⱼ
      (e.g., primes: 101, 103, 107, 109, 113...)
2. Compute product modulus:
      M = m₁ × m₂ × ... × mⱼ
3. For each swarm i:
      Mᵢ = M / mᵢ
      Find Yᵢ such that Mᵢ × Yᵢ ≡ 1 (mod mᵢ)  [modular inverse]
4. Apply Chinese Remainder Theorem:
      Kₑₙ = Σ (Mᵢ × Yᵢ × swᵢ) mod M
5. Store Kₑₙ on blockchain with timestamp
6. All swarms can independently compute Kₑₙ using public data
CRT Advantage: Enables threshold encryption where any t-out-of-J swarms can reconstruct the key. Provides fault tolerance and distributed trust.

📐 CRT Theorem: Unique solution Kₑₙ exists modulo M given residues swᵢ modulo mᵢ

Kₑₙ ≡ sw₁ (mod m₁), Kₑₙ ≡ sw₂ (mod m₂), ..., Kₑₙ ≡ swⱼ (mod mⱼ)

Algorithm 5: Inter-Group Session Key Distribution
Phase 5 • Secure Multicast
INPUT: Composite key Kₑₙ from blockchain, swarm private keys
OUTPUT: Shared Inter-Swarm Session Key K_cr

1. Initiator swarm selects random session key K_cr ∈ [1, M-1]
2. Encrypt using ElGamal encryption:
      c₁ = K_cr × (Kₑₙ)^s mod M
      c₂ = g^s mod M  (where g is generator)
3. Send (c₁, c₂) to all target swarms via GCS
4. Each recipient swarm i decrypts using its private key Kᵢ:
      K_cr = c₁ × (c₂)^(-Kᵢ) mod M
5. Verify using HMAC: HMAC(K_cr, nonce) == received_tag
6. Establish secure inter-swarm channel with K_cr
Security Guarantees: Confidentiality via ElGamal, authentication via HMAC, and perfect forward secrecy through ephemeral session keys.

📐 Decryption Proof: c₁ × (c₂)^(-Kᵢ) = K_cr × g^{sKₑₙ} × g^{-sKᵢ} = K_cr when Kₑₙ ≡ Kᵢ (mod mᵢ)
